## Event input contract

`TranscriptEvent` contains the audio **source channel** (`remote`, `microphone`, `unknown`), stream generation, segment ID, revision, monotonic start/end milliseconds, partial/final/retracted/discontinuity status, verbatim text and optional ASR confidence. The caller may supply a **tentative intent** (`question`, `correction`, `follow_up`, `statement`, `unknown`).

The supplied intent is not semantic proof. The module neither infers a complete interviewer identity from remote audio nor treats spoken instructions as application instructions. A remote channel may mix multiple interviewers. Low confidence (when a numeric value is actually supplied) blocks question routing; the 0.60 threshold is a provisional guardrail, not a calibrated probability. Missing confidence does not establish high accuracy.

Only final, sufficiently unambiguous remote question events may produce a `TurnDecision(state="ready")` with a `QuestionSnapshot` and the *shared* `TurnToken`. Partial text never starts inference. Unknown or microphone-channel utterances do not create remote interview questions. Intent labels and transcript text are untrusted inputs; in later slices a separately evaluated classifier must decide when to label them.

## State, timing and privacy semantics

- Every accepted correction/follow-up snapshot carries a bounded ordered list (at most 16) of accepted source segment IDs **and their original accepted source intervals**, with no duplicated transcript text. A later retraction of **any** contributing correction, not merely the original root or current utterance, cancels the active talking point. Unclassified remote speech overlapping **any source interval still contributing to the current answer** cancels as well: if A spans 0–1000 ms and correction B spans 1100–1200 ms, a delayed unknown 500–800 ms invalidates B, even though it predates B. A completely independent later question resets both the dependency IDs and their intervals so stale speech from unrelated prior questions cannot cancel the new one. The semantic accuracy of those transcripts remains unverified.
- Each active logical question has one ID and version. A genuine new question gets a new ID and version one. A correction or follow-up increments the existing logical version and, through `ActiveTurns.activate`, replaces its generation. Old answers become stale **before** they can publish. In chained corrections the immediately preceding accepted wording stays separately labeled from the original, so a later correction like 'make that 2024' does not silently re-enable a superseded 'by revenue' metric.
- The same dependency safety applies while a correction/follow-up is still **partial**: its interrupted prior snapshot retains the accepted timing spans. A delayed unknown final overlapping any retained span invalidates the pending correction, clears its context and marks that pending segment ineligible for later automatic publication. Higher-revision finals or partials, and conflicting **same-revision** finals, of **any** contributing accepted segment also invalidate the latest dependent turn; revised source text is not silently applied to prior approved wording.
- An old reopened segment remains quarantined against a later revised final, but its unrelated retraction must not cancel a genuinely newer independent question. Previously unseen stale partials whose original start precedes a newer accepted question do not preempt that question solely by arriving late. These protections are tested separately from actual model/ASR semantics.
- A remote partial explicitly labeled question/correction/follow-up invalidates a previously active answer immediately. For matching eventual correction/follow-up finals, only the previous accepted verbatim context is held provisionally. The partial **cannot** become an answer, and a discarded project question in E11 cannot be treated as authoritative.
- D12 preserves the literal corrected request about **distinct orders in 2025** as authoritative. Earlier question wording is included in a separately labeled superseded/context-only field, never silently merged into a newly fabricated SQL predicate, ranking metric, tie policy or database dialect.
- E04/D07 multi-part splitting is a reversible **verbatim heuristic hint**, never a semantic parts-coverage or answer-correctness certificate. The complete user-provided transcript stays available as one current utterance.
- Exact same-segment revision replays are ignored using SHA-256 fingerprints. Retraction of a root segment while a correction partial is pending invalidates that dependent correction and disqualifies repeated late finals of the pending segment; the same remote stream generation may still accept a later unrelated question. Only an ASR stream discontinuity or explicit user stop blocks the whole generation. Conflicting same-revision finals, **higher-revision partials reopening a current final** (immediate cancellation), post-final ASR revisions, retractions and stream discontinuities invalidate any old active answer. A reopened final may not silently re-enter answer routing, even after a revised final arrives **with an unchanged source timestamp**. Old remote stream generations, late finalizations of previously seen partials, and revisions or retractions of an already superseded segment cannot regain control or cancel a newer answer. A newly finalized unclassified remote utterance invalidates the previous answer, and overlapping remote question timestamps require review rather than assuming one speaker.
- Replay bookkeeping holds at most 128 opaque segment summaries, not complete transcript history. Each segment retains its **earliest observed** source start time across ASR revisions, including in the leading-partial cursor (which preserves its first observed end), preventing a delayed old correction from fabricating a later interval and taking over a newer question. The current finalized segment, **all unresolved partials (including abandoned old ones)**, pending correction/root and reopened-final metadata are protected from ordinary LRU eviction, with explicit fail-closed handling if protected context alone exceeds capacity. Revisions of a previously reopened final cannot cause another tentative partial to supersede a newer independent question; they remain quarantined pending an explicit host resolution. A separate **single newest tentative partial-segment cursor**, together with a monotonic question-start watermark, prevents abandoned older partials from regaining authority after newer complete questions even if their delayed final extends beyond the new question's end timestamp; the cursor is cleared on the matching final, on a clearly newer **non-overlapping** finalized utterance, or on a stream reset. A different final that overlaps pending remote speech produces needs_review rather than guessed speaker ordering. Stale retractions of superseded questions cannot cancel a newer active turn or clear another segment's reopened-final quarantine, including after the old record has been evicted from the 128-entry ledger. Active/current context is bounded; nothing is written to a file or sent to a model.
- Explicit stop/permission removal blocks **every** subsequent generation until `resume()` is invoked by the native host. Calling `resume()` in Python does **not** prove actual OS permission or user consent. A stream discontinuity blocks the affected generation until a new generation arrives.
- Numeric stream generation, segment revision, start and end timestamps are validated as **UInt64**-bounded Python integers before JSON replay fingerprinting. Both transcript text and segment IDs must also encode as strict UTF-8: lone surrogate code points are rejected before hashing. Nonempty finalized text with zero source duration (`start_ms == end_ms`) is also rejected with stale-turn cancellation: a native host's nanosecond-to-millisecond rounding may collapse genuine short utterances into a single millisecond, but Relay cannot safely treat such an unclassified final as a harmless stale segment. Malformed remote events cancel the active/pending answer even when validation fails; they raise sanitized `InvalidTranscript` rather than presenting stale output. Invalid microphone-only events do not cancel a remote question. These are synthetic safeguards and not native clock or permission attestation.
- `ready` means the calling adapter may consider routing to a separately authorized QA/inference step, not that the speaker was identified, the question semantically understood, or the AI answer verified.
- [publish_assessment](https://github.com/KanujVerma/relay/blob/88af72044b4dd0127bba869b8783803a2769ec40/relay_spike/streaming_qa.py) still checks the token **at the synchronous publication boundary**. A stale completed model response never displays after a correction, interruption or stop.

## Scope and next integration

The [synthetic regression suite](https://github.com/KanujVerma/relay/blob/88af72044b4dd0127bba869b8783803a2769ec40/tests/test_question_turns.py) covers E11 discarded partial questions, D12 corrected SQL metric/date, E04/D07 multi-part wording, follow-ups, partial-to-final replacement, interrupted in-flight QA publication, low-confidence uncertainty, mic/remote overlaps, duplicate/stale events, stream-generation resets, stops/retractions and sanitized error handling.

B0 does **not** wire into FluidAudio, capture Zoom, recognize actual questions from arbitrary natural language, import Private Brain facts, invoke ChatGPT OAuth or measure first-useful-answer latency. After real, permission-checked Mac audio/ASR evidence exists, a separate bounded integration slice may adapt finalized transcript event metadata, test an independent intent classifier, and connect this machine to the existing safe `live-qa` publisher. Keep the M2 Pro 16 GB CPU/RAM budget and permission constraints explicit. Never present a purported useful talking point before independent validation.
