## Storage checkpoint

`protected_storage.py` extracts the existing permanent interprocess flock, macOS FULLFSYNC/POSIX sync and durable temporary/rename/parent-sync mechanics from auth.py. Existing CLI entrypoints delegate to them;45 auth/spike regressions stay green. Existing unsafe permissions/links now fail closed instead of being silently repaired. Product data is ciphertext before the temporary file is created. The CLI remains explicitly a plaintext spike and is not a product credential source.

`AccountCredentialStore` requires an actual32-byte key and absolute directory, with no IO at construction or legacy file fallback. Explicit initialize persists one opaque host UUID. The AESGCM registry holds at most8 registrations/1MiB, authenticates its fixed version header and uses fresh96-bit nonces. Exact issuer/subject/issued-client mappings are separate from email. Store validation does not verify an ID token: only the forthcoming OAuth service may commit a registration after actual signature/identity/nonce validation.

The store binds token access to actual selected registration/generation and current plan scope, reloads under the same permanent interprocess lock, and commits complete rotations durably before returning access. A persisted refresh-intent blocks reuse after process death, unclassified failure or post-success write failure. Confirmed transient AuthError preserves the original grant; terminal/malformed success clears secrets and retains registration. Sign-out first persists denial, then clears only token material while preserving host/account mapping. Public metadata excludes tokens and private subject/client IDs. All filesystem and auth errors remain fixed/sanitized.

Native `KeychainProfileKey(purpose: .chatGPTCredentials)` uses only `com.relay.chatgpt-auth.v1` / `local-chatgpt-aes256`. Default `.profile` is unchanged. Existing copy/add-only behavior, device-local/non-sync storage, missing-versus-locked handling and inert construction remain shared. No rotating Keychain setter, profile consent change, key replacement or actual Keychain operation was added to tests.

## Exact checkpoint API

Python constructor `AccountCredentialStore(directory:Path, key:bytes, now=time.time)`. Methods: `initialize()->str` host ID; `save_registration(record, registration_id=None)->str` internal verified-OAuth boundary; `select(registration_id,generation)`; `metadata()->dict` no token/private identity; `registration(registration_id)->dict` private reconnect/revocation input; `active_access_token(registration_id,generation,refresh=None)->str`; `begin_sign_out(registration_id)->dict` private revoke input after durable denial; `finish_sign_out(registration_id)`. The synchronous injected refresh callback returns token JSON or classified auth errors and executes while the cross-process lock is held. Unknown exceptions keep the durable uncertainty blocked. No network transport is implicit.

Native fixed enum `KeychainKeyPurpose.profile|chatGPTCredentials`; initializer `KeychainProfileKey(purpose: KeychainKeyPurpose = .profile, client: SecurityItemClient = SystemSecurityItems(), random: ... )`. It still conforms to existing ProfileKeyProvider and performs no lookup on construction. These methods are actual implemented storage ports, not UI authority DTOs.

## Control and protected-provider checkpoint

`AccountOAuthService(store, client_factory=..., sync_client_factory=..., listener_factory=..., now=...)` is inert until explicit methods run. `connect(registration_id, publish_authorization, enable_plan=False)` returns a grant only after the existing PKCE/callback/client/OIDC signature, issuer/audience/expiry/nonce and scope checks. It never activates the store itself. An actual tracked loopback listener is closed/joined on cancellation; HTTPX uses bounded bodies, no redirects/proxy environment or cookie reuse. Reconnect retains verified issuer/subject/issued-client mapping and uses optional hints; an oversized ID-token hint is omitted before publishing the private URL. Explicit plan enable requests consent. No SDK implementation or provider assets were copied.

`refresh(record)` is one synchronous classified HTTPX token call while the store owns its permanent refresh lock. `catalog(registration_id,generation)` reloads that exact selection/bearer, fetches the documented catalog and keeps visible entries in server order. `revoke(record)` discovers the exact auth-origin endpoint, posts the refresh-token form and confirms only empty HTTP200; each attempt has a five-second total bound. The bridge makes at most two attempts with bounded backoff. Local sign-out denial is durable before the first attempt; clearing token fields preserves registration/host mapping, and unconfirmed remote revocation is explicit.

`read_bootstrap_fd(fd,purpose,timeout=3)` consumes **exactly one** BE32 private frame, using `select` and `os.read` before attaching an asyncio reader. Its strict seven fields are schemaVersion/kind/purpose/key/vaultDirectory/registrationID/accountGeneration. `ProtectedAccountSession(bootstrap, service_factory=...).open()` validates actual encrypted selection/generation/plan scope without network; `.token()` reloads/rotates the same store at use. Neither path invokes legacy `load_auth`, imports old spike credentials or treats a serialized boolean as authority. Missing/wrong-purpose/truncated/late bootstrap fails without fallback.

`AccountBridge(bootstrap, emit=..., service_factory=..., on_failure=...)` plus `await start/handle/drain/close` owns the approved exact five-key request/eight-key response protocol. `run_stdio(bootstrap,input_fd=0,output_fd=1,service_factory=...)` and `python -m relay_spike.account_bridge` are actual implementations, not protocol stubs. There are no command-line auth/secret/runtime mode flags. Status returns cached metadata without refresh/network. One tracked operation and owned file/lock threads stay off the reader. Cancellation revisions become terminal only after actual worker cleanup; a hung lock still requires the native owner's process-exit receipt. The writer is bounded to32 frames/256KiB with drain/partial-frame deadlines. Unexpected errors close the channel without provider text.

Request actions/payloads: status/models `{}`; connect `{registrationID:UUID|null}`; enable_plan/select/sign_out/acknowledge_plan_notice `{registrationID:UUID}`; cancel `{targetRequestID:UUID}`. Responses retain the approved fixed status/reason enums and cached public last-check snapshot. Private authorization is a separate four-key effect bound to the pending UUID and exact HTTPS authorize endpoint, never the public DTO. The512-entry ledger prevents repeated IO; the latest8 replies replay exactly, with active operation pinned. An evicted replay or altered UUID payload closes the channel rather than creating an orphan competing terminal. Native must own that process exit. A restart needs a new explicit native private bootstrap; status alone does not issue an inference selection.

Joint16KiB budgeting includes escaped JSON and a reserved response envelope. Every complete registration summary is kept. If the complete visible catalog cannot fit, models are empty and catalogState is unavailable; no partial list is mislabeled current. Account readiness/identity validation time remains distinct from current model availability or image capability. The later native controller will choose the first visible current model automatically and may expose an optional advanced override, instead of requiring a front-facing model choice.

New tests exercise generated RSA/JWKS signature verification over **HTTPX MockTransport only**, actual private pipe/child framing, cancellation-ignoring workers, repeated cancel and cached replay, exact bounded ledger, worst-case escaping/UTF8 catalog budgets, optional-hint omission, and the **actual OAuthAnswerStream** consuming a protected bearer then a durably rotated bearer. Sign-out prevents another model POST. These are synthetic library/owned-child results, not an actual app/Keychain/account/model acceptance. The product join must still enforce private bootstrap before any OAuth construction, prepare the fixed shared Relay parent as0700 before Accounts, and retire/join inference before identity/mode mutation without changing Personal Brain consent.
