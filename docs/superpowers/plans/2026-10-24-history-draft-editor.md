# Bounded manual History draft completion

Controller approved direction and this exact minimal API after independently accepting the b367 reentry boundary. This is manual notes only, not generated notes, biography approval, autosave or persistent unsaved drafts. The existing store/schema/key/retention/capture/helper policy remains unchanged.

## Minimal APIs

- `HistoryRecordsUnavailable` is a read-only, non-Codable notification with internal initializer, `retiredEpoch: UUID` and `recordIDs: Set<UUID>?` (`nil` means every record in that retired workspace scope). `SessionHistoryCoordinator.onRecordsUnavailable` is default nil; the Model owns its callback. It is denial-only and cannot open/read/authorize records. Explicit matching Delete sends after its private tombstone/exclusive ownership is registered and before publication. Lock, Delete All and owner-close send all for the old epoch after synchronous retirement ownership is registered, before publication. Stop saving and source deletion preserve the independent manual draft.
- Actual expiry removal returns a bounded destructive-mutation receipt: `HistoryStore` retains at most100 expired IDs produced only after actual removal commits; the one owned coordinator storage flight consumes/clears them once even if the enclosing operation throws. This is a volatile per-operation receipt, not a persistent record registry, lookup or source of admission. The coordinator checks original workspace epoch and exact store object ownership before applying those denial IDs, clearing matching selected/private retention state and invoking the callback. Callback runs on MainActor after the detached storage call/receipt drain releases every store lock and before snapshot publication. Old callbacks cannot clear replacement state. No expiry is inferred from list/page absence.
- `@discardableResult saveNotes(...) async throws -> HistoryNoteSaveReceipt` preserves arguments and actual CAS. Non-Codable receipt has internal initializer and actual workspace epoch, recordID, new revision, exact saved title/note. It is issued only after the existing owned save/result fences, never synthesized from a mutable UI snapshot. No stored shape changes. Existing callers may discard it.
- New app-only `@MainActor HistoryNoteDraft` owns one bounded private editor and coalesced published snapshot: binding UUID, workspace epoch, recordID, expected revision, saved title/note baseline and current fields. Total strings<=2*(120+8192)UTF8bytes. API: `stage(record:epoch:discardingChanges:) -> Bool`, `editTitle`, `editNote`, `discard`, `invalidate(HistoryRecordsUnavailable)`, `save(using:) async throws`. Same-record/same-binding reopen preserves a dirty draft; a changed record/revision requires explicit discard/review. Save captures its binding/edit revision and updates baseline only from the matching actual receipt. A newer edit during Save stays dirty; Lock/new binding/old receipt cannot restore private text. Constructor/staging/edit/discard perform no IO.

The Model owns this editor for its app lifetime and connects the owned notification; ordinary window destruction therefore preserves the bounded draft. `RelayHistoryWorkspace` observes it instead of local title/note @State. One existing-style discard confirmation protects dirty record navigation/refresh; Cancel performs no IO. Existing Save is the acknowledgement. Failure keeps the exact draft and CAS revision, with truthful recovery. Existing record Delete confirmation clears its matching draft through the coordinator prefix; no second confirmation is added. Lock/purge/owner-close clear synchronously. Audio End/account refresh leave an unlocked draft alone. Source deletion preserves user notes/draft but can make its CAS stale; it does not silently rebase or overwrite saved notes.
