# Protected ChatGPT account setup design

2026-10-23. **Approved engineering design; implementation is a separate active lane.** Isolated design clone `work/relay-account-design`, branch `design/chatgpt-account-setup-2026-10-23`, clean at `666d104ffff82dd17112872be08e4ef76e01adfe`. The stock nested-runtime correction `63be1f135309cca66c23e9471632155488c06fda` is a read-only dependency for the later join. Typed source/PR83 remains separate. This is an architectural slice because protected storage, account operations and helper bootstrap cross native/Python ownership.

## Recommendation and minimum honest product

Ship Continue with ChatGPT, a saved-registration picker/status, reconnect, explicit plan-permission enablement, sign-out and an account-specific model picker. Preserve offline/AI-off behavior as an explicit mode. Do not ship legacy plaintext credential fallback, silent migration, API keys, cookies, hosted backends, model probes at startup, usage estimates or a Connected badge that implies current model/capability entitlement. Standalone idle Ask is separate from account setup.

Use a **separate immutable native Keychain AES256 key**, delivered over the existing inherited-pipe pattern, and a **Python AESGCM credential registry** with the reviewed interprocess refresh lock and durable rotating-file replacement. Reuse the existing OAuth protocol checks and HTTPX/SSE engine. The Keychain key never rotates as part of OAuth refresh; access/refresh/ID/scope/expiry state rotates together as one encrypted payload. Personal Brain key, approval, Lock and facts remain independent.

## Verified source facts

Official [sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) requires new dynamic registration, a stable host ID, exact loopback redirect, fresh PKCE/state/nonce, verified ID-token signature/issuer/audience/expiry/nonce and granted-scope checks. Registration identity is the verified issuer/subject plus issued client ID; returning identity must match. [Accounts/sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) requires separate registrations even with identical emails, stable labels, reuse of client/host mapping and serialized refresh. Sign-out stops requests, attempts refresh-session revocation using discovery, then clears local tokens; unconfirmed remote revocation must be disclosed. These requirements do not grant access to ChatGPT conversations or memory.

[Models/inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) requires the selected account's current catalog and same bearer; visible model choices preserve server ordering and use the slug. Responses is the public endpoint, with completed-terminal success. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) still apply. Catalog presence and sign-in do not prove optional image/model capability. [Recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery) distinguishes missing plan scope, terminal refresh errors, transient failures and usage limits; no disconnection notification is promised. [UI guidance](https://developers.openai.com/siwc/ui-ux-guidelines) calls for Continue with ChatGPT, a first successful plan-use explanation, visible plan-use indication and Manage usage. Relay will not offer an alternate paid API path.

Actual local `auth.py` is explicitly a0600 plaintext CLI spike. Its permanent no-follow flock, double-read refresh, terminal/transient classification and strong-sync atomic replacement are reusable. Monolithic `sign_in()`'s printing/browser/disk globals are not a product GUI API. `KeychainProfileKey` in `ProfileVault.swift` is the actual native primitive: injected OS client, device-local/non-sync, exact item lookup, missing distinguished from locked/error, no construction access or key replacement. ProfileVault's AES-GCM snapshot pattern is useful, but its `.atomic` save lacks auth.py's rotating-credential durable sync. Existing OAuthAnswerStream already injects a token provider and uses HTTPX0.28.1, redirects disabled, bounded SSE/ResponseAssembler and current visual receipts.

## Storage and process ownership

1. Native owns the OS key. Prefer a narrow fixed-purpose parameter on the existing provider, defaulting unchanged to profile; `.chatGPTCredentials` maps only to service `com.relay.chatgpt-auth.v1` / account `local-chatgpt-aes256`. Reuse its injected SecurityItemClient and tests. No generic Keychain enumeration or arbitrary user-supplied namespace. Root must approve/coordinate that one ProfileVault.swift seam before any edit.
2. Python `AccountCredentialStore` owns one encrypted registry and its permanent owner-only lock in the app's fixed Accounts directory. Maximum8 registrations,1MiB plaintext,32KiB per token, bounded labels/claims. All email, issuer/subject/client mappings, tokens, scopes and account selection metadata are inside ciphertext. A fixed version header is AAD; nonce/ciphertext/tag are the only file content. Temporary files also contain ciphertext only. Validate owner/type/link count/mode/size/no-follow paths; refuse corruption, unsupported sync, broad permissions or unsafe location. Never overwrite a corrupt store or generate a new key for an existing vault.
3. Extract parameterized protected lock/durable-byte-replace primitives from existing auth.py mechanics, keeping CLI wrappers/tests unchanged. Every mutation/refresh takes the same actual interprocess flock, reloads the latest encrypted state, performs at most one exchange and durably replaces complete credentials before returning the new access token. No native snapshot token provider or per-process-only mutex. Confirmed terminal/malformed-success refresh quarantines token secrets while retaining registration. Transient failures preserve credentials. Disk-write failure after server rotation is not success; require reconnect/retain blocked state, never report a saved rotation. Crash between server rotation and local durable commit can still require reconnect; do not promise a distributed transaction/power-loss guarantee.
4. An `account_bridge` control child owns one cancellable sign-in/revoke/catalog operation; a nonblocking control-owner flock prevents a second app instance changing selection concurrently. The existing session helper independently reads/refreshes the same encrypted store. AccountController invokes the root's actual inference-retirement closure and waits for request/producer/helper quiescence **before** connect/reconnect/enable-plan, selecting/signing out or changing AI mode. This avoids needing a second activation commit from a browser attempt while old inference is live. The account UI is idle-only during capture; actual root cleanup remains required even when UI says idle. Only after validated durable account activation can root start a fresh helper; declined/cancelled login never automatically resumes old inference. Bootstrap selection/generation is checked again whenever credentials are read. Root retains the existing post-token/current-request/publication fences. Refresh invalidates existing bearer-bound visual proof; it never upgrades image permission.
5. Profile consent does not derive from OAuth identity. Account sign-out does not delete the personal vault; profile Lock does not sign out ChatGPT. Reaping a shared session helper drops its in-memory provider authority; root may reload only its still-explicitly-open, current approved profile through existing gates. No account subject is repurposed as a personal-memory identity.

### Private bootstrap

Only native-held private bootstrap construction can read the OS key. The owned child's **first** BE32 frame, at most16KiB, has exactly7 fields: `schemaVersion:1`, `kind:account_secret_bootstrap`, `purpose:account_control|oauth_session`, `key:base64(32 bytes)`, `vaultDirectory:fixed absolute app path`, `registrationID:UUID|null`, `accountGeneration:UUID`. The pipe is inherited stdin, not environment, argv, a temporary plaintext file, profile RPC or public AccountSnapshot. Key/secret wrappers have redacted debug output and no Codable public surface. No key/token/personal content is logged. Missing/late/replayed/wrong-purpose bootstrap fails the protected product invocation; no legacy load_auth fallback. Non-OAuth/profile/fixture invocations retain their existing protocol and cannot opt into secret bootstrap accidentally.

This does not promise secure memory erasure, protection against same-user debugging or removal from backups. No real Keychain/browser/login is used in development tests.

## Native API and strict wire proposal

New `RelayAccount` module, constructor-inert main-actor `AccountController`:

```swift
init(port: any AccountPort,
     keyProvider: any ProfileKeyProvider,
     retireInference: @escaping @Sendable () async throws -> Void,
     openAuthorization: @escaping @MainActor (PrivateAuthorizationURL) -> Bool)
func restore() async
func connect(registrationID: UUID? = nil) async
func enablePlanUsage(registrationID: UUID) async
func cancelConnection() async
func select(registrationID: UUID) async
func signOut(registrationID: UUID) async
func refreshModels() async
func acknowledgePlanNotice(registrationID: UUID) async
func close() async
```

Root injects the actual protected key purpose and helper retirement. Constructor/view rendering does no IO. Restore is an explicit lifecycle action, separate from profile unlock; locked storage is shown truthfully. `AccountPort` privately bootstraps the owned child and returns progress/terminal DTOs; close/cancel joins the actual operation or stops/reaps that child through an exit receipt. Cancelling a Swift Task alone never certifies cleanup. Python callback/network work stays off the stdio reader; one actual operation, no sign-in retry or network side effect on status. Status returns cached public last-check state promptly instead of waiting behind a network-held refresh lock. If a blocking legacy worker cannot join, reap its child before allowing new account work. Reuse pure PKCE/callback/token validation; use injected bounded no-redirect HTTPX for product operations, rather than invoking the monolithic CLI sign_in.

Public `AccountSnapshot` exact5 fields: `revision:UInt64`, `activeRegistrationID:UUID|null`, `registrations:[AccountRegistration]` (max8), `models:[AccountModel]` (max32), `catalogState:unloaded|loading|current|unavailable`. Registration exact8: `registrationID`, `label` (max80UTF8), `email` (max254UTF8|null), `identityState:validated_at_sign_in`, `planUsageState:granted|not_granted|unknown`, `sessionState:available|signed_out|reauth_required|signing_out`, `lastValidatedAt:UInt64` UTC seconds, `planNoticeAcknowledged:Bool`. The latter is only a local presentation preference, never plan consent/authority. Model exact2: `slug` (max128UTF8), `displayName` (max160UTF8), no controls. Registration identity/private scopes are not serialized publicly. Opaque local registration UUID is only UI selection, not verified person/workspace identity. Email is a validated token claim, not a unique registration or automatically verified-email claim.

Request exact5 fields: `schemaVersion:1`, `kind:account_request`, `requestID:UUID`, `action`, `payload`. Payload schemas:

| action | exact payload | Behavior |
|---|---|---|
| status | `{}` | Local state only; no credential network call/refresh |
| connect | `{registrationID:UUID|null}` | New registration or reconnect selected mapping; keep attempt separate until validated/durably saved |
| enable_plan | `{registrationID:UUID}` | Explicit complete-scope re-consent; no ordinary-login consent loop |
| cancel | `{targetRequestID:UUID}` | Cancel the actual owned connection operation, wait for cleanup |
| select | `{registrationID:UUID}` | Only after root retirement; selected registered credentials must match identity/mapping |
| sign_out | `{registrationID:UUID}` | Block admission durably, revoke/clear selected secrets, retain registration/host mapping |
| models | `{}` | Fetch active account catalog with its actual bearer; never infer |
| acknowledge_plan_notice | `{registrationID:UUID}` | Persist the first-plan-use notice dismissal; grants no permission, makes no network request |

Response exact8: `schemaVersion`, `kind:account_response`, `requestID`, `action`, `resultRevision`, `status`, `reasonCode`, `snapshot`. One optional pending revision1 and exactly one terminal2; terminal cancellation means actual cleanup. Status fixed enum `pending|ready|signed_out|locked|reauth_required|plan_disabled|busy|cancelled|unavailable|error`. Reason fixed enum `current_status|connected|plan_permission_missing|reauthentication_required|storage_locked|storage_unavailable|authorization_pending|authorization_declined|authorization_failed|authorization_cancelled|account_selected|signed_out|remote_revocation_unconfirmed|catalog_updated|catalog_unavailable|operation_busy|protocol_rejected`. No raw server exception/body/code text or tokens. UInt64 rejects bool/float; strict keys/UTF8/UUID/no-controls,16KiB framing,512-operation ledger/8 cached latest replies. Exact replay returns latest state without browser/network IO; changed UUID reuse fails closed.

Authorization URL is a separate **private** exact4-field effect: `schemaVersion`, `kind:account_authorization`, `requestID`, `authorizationURL`. Native binds it to the current pending request and permits only HTTPS auth.openai.com's exact documented authorize endpoint; it opens via NSWorkspace, never a shell command. ID-token hints can be secret, so this effect is not public/published/logged. The callback remains the existing actual127.0.0.1 listener with matching Host/path/state/client/PKCE/nonce checks; it closes on cancellation/timeout. A failed browser-open cancels the owning attempt. New identity cannot replace an existing selected registration before verification.

## Sign-out, limits and runtime join

Persist a `signing_out` denial before revocation so a crash cannot resume that grant. While holding mutation ownership, attempt documented discovery-bound revocation with bounded retries/backoff (two5s attempts,0.5s delay); keep reader responsive. Empty200 is confirmed success. Then durably clear access/refresh/ID tokens, retain only mapping/host/last identity, close owned secret processes and drop key references. Local clear failure is an error, not Signed out. On unconfirmed remote revocation, clear locally and say the user can disconnect the app in ChatGPT Settings. No background retained-token retry after local completion. A restart with a signing_out record cannot infer; it offers cleanup/reconnect.

Identity-only login remains signed in with plan disabled; Enable ChatGPT plan repeats OAuth under explicit consent. Models are fetched on connect/select/explicit Refresh, using visible entries/server ordering and the selected account's bearer. Model selection is bounded server data and still may fail a real request. Do not interpret unavailable account/workspace details as entitlement or permission to change billing. Usage-limit UI points to Manage usage without invented reset time. Last validated identity/catalog state is distinct from current request success and the existing explicit visual probe.

Root-owned join extends the packaged entry allowlist only with `relay_spike.account_bridge`, adds strict private bootstrap for product OAuth session startup, and injects the store's synchronous active_access_token into the existing stream factory. SessionHost main needs a narrow injected stream/provider entry seam; CLI defaults remain development-only. HelperTransport must pass a bounded selected model slug as `--model` and send bootstrap first; currently it passes only role/mode. Product OAuth missing a bootstrap cannot invoke auth.py's plaintext path. No external Python fallback, new SDK, arbitrary module or dynamic import. Include resolver63be1f1, current packaging lock/notices and a relocated frozen-runtime regression before product acceptance.

V1 does not silently read/import/delete the old spike-host/spike-oauth files. A fresh GUI registration is separate; any legacy-registration migration requires a separately explicit design/action. The preview's OSS/local-hosted scope and actual integration/account eligibility remain acceptance gates, not consequences of implementing UI.
