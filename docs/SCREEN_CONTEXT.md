# Optional selected-window context

Issue #64. Implemented as the independent `spikes/macos-context` Swift library; final app composition belongs to the answer/controller lanes. Library launch, settings-model construction and tests do not request permission or read user screens. A real user must choose **Enable and choose window**, then select one window in Apple's public system picker. No app/display fallback, keyboard monitoring, external-app Accessibility reading, private APIs, screen-share hiding or automatic frontmost-app capture is implemented.

## Implemented native API

`ScreenContextModel` and `ScreenContextSettingsView` provide explicit selection/disable, source/age, transient image preview and extracted-text preview. They require macOS 15.2+ because `SCContentFilter.includedWindows` exposes selected window/app identity there. The package's lifecycle/types remain macOS 14+. Callers must visibly disable the optional feature on older systems; other packages need not raise their minimum.

`ScreenRequest(sessionID, sessionEpoch, presentationGeneration, requestID)` preserves the original native request fences. `ScreenContextCoordinator.capture(for:budgetNanoseconds:)` returns a snapshot or typed unavailability. Default budget is 1.5 seconds, maximum admitted budget is 2 seconds. Source/permission/selection revisions and request IDs are captured before the first await. A new question, source change, source closure, disable/revoke, cancellation or deadline retires old observations before the invalidation callback. At most one capture/OCR/recheck runs. Timeout/cancel resumes its waiter promptly while retaining busy backpressure until the underlying OS/Vision call actually quiesces.

The public adapter retains the system-selected filter and uses `SCScreenshotManager.captureImage`. Capture verifies selected window ID, owner PID and app bundle before/after the screenshot. Metadata checks use the one selected window only; no image or broad source enumeration is performed. No broad TCC request or AX request is added. The screenshot is SDR, cursor-free, at most 1920 on its long side and never upscaled. No actual permission, window closure or selected-content runtime acceptance has been performed yet.

Vision's `VNRecognizeTextRequest` runs on a dedicated serial queue with `.accurate`, local English recognition, language correction off and explicit cancellation. Recognized line boundaries, normalized bottom-left boxes and OCR confidence are retained. Text is at most 8192 UTF-8 bytes, at most 256 observations; overflow fails without silent truncation. No code indentation or symbols are reconstructed. Diagram labels are OCR evidence only, without inferred arrows/relationships. A synthetic short `API` label produced Cyrillic lookalikes during testing; OCR does not establish exact identifiers, syntax or correctness. Source preview and user-provided problem text remain necessary fallbacks.

## Observation validity and publication

`contentDigest` hashes original OCR text plus normalized line placement quantized to 1/1000; confidence is excluded. `imageDigest` separately hashes canonical original RGBA pixels and dimensions. A pixel-only caret/animation change need not invalidate unchanged OCR text. A text/layout change does invalidate it. Neither digest supplies authority by itself.

On answer-ready, the final app calls `validateForPublication` or `coordinator.validateCurrent(snapshot, for:request, budgetNanoseconds:500_000_000)` once. It recaptures the same selected source and recognizes text within a bounded deadline. The original snapshot timestamp, request, revisions and image identity are retained. After the await, synchronously check `coordinator.owns(snapshot, for:request)` AND the original native presentation lease before committing a card. On false/timeout/error, withhold screen-dependent output and retire its lease before helper/UI callbacks. Age is capped at 10 seconds; time alone never proves code unchanged.

This is a rechecked captured observation, not certification of the user's screen at paint time. A source can change after the recheck; that TOCTOU interval is explicit. There is no always-on capture loop. Newly observed content changes retire prior context; the UI identifies capture age and provenance. Screen evidence is untrusted task material, never instructions, personal biography or confirmed project contribution.

## Shared port and image capability

The controller owns the canonical shared schema. Supplemental text uses a separate `screen_context` message and the answer lane's `ContextSnippet(kind="screen_text", provenance="local_ocr")`; the exact 13-key inner EOU event is untouched. Source descriptor: `{windowID,bundleID,processID,label}`. The native producer must invalidate the Python provider and pending answer admission when its source authority changes. A timestamp or a serialized `authorized` flag cannot grant source authority.

Official OpenAI [plan-usage preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) retrieved 2026-10-23 explicitly support text/images/files when the selected model accepts them; audio/video input and the Files upload API are unsupported on that route. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) require a model available to the selected account and the public Responses endpoint with `store:false, stream:true`. These documents establish the route's conditional image capability. They do not establish this user's selected account/model image acceptance, latency or output accuracy. Relay's current answer transport remains text-only. The new optional bounded image port is offline code; it does not perform network requests and production image use defaults off until model support and user image enablement are established. No image upload/live inference is authorized or tested in this lane.

Raw images exist transiently in memory for preview/capture/optional transfer. Disable/revoke/new request clears the retained preview. No raw image, extracted private text, user screenshot or OCR error payload is written to disk, logs, Git or CI. Explicit retention is not implemented.

## Reuse and verification

Exact upstream source/license, rejected alternatives and actual reuse are in the package's [third-party record](../spikes/macos-context/THIRD_PARTY_NOTICES.md). Apple's public capture/OCR frameworks are invoked directly. No competitor code, prompts, assets or service implementation is copied. Sanitized Cluely 2.1.24 research motivated request-bound capture/preview but did not establish backend vision behavior.

The lane handoff records current commit/check status. Synthetic tests compile the actual adapter but never call its picker. Vision uses generated in-memory code/problem and diagram-label images. Real user selection/denial/revocation, app packaging and account-model image acceptance are separate unperformed gates. A first native Vision initialization took about 50 seconds; warm synthetic OCR took roughly 0.1-0.3 seconds per image on this Mac. Neither figure measures live interview latency. Sandbox Vision calls returned `nilError`; approved synthetic-only tests outside the filesystem sandbox passed.
