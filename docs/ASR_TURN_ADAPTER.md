# Relay 03B-B0: synthetic final EOU transcript and intent contract

**Status:** [PR #46](https://github.com/KanujVerma/relay/pull/46) is a synthetic-only child of [issue #45](https://github.com/KanujVerma/relay/issues/45) and [issue #43](https://github.com/KanujVerma/relay/issues/43), based on the independently reviewed, merged 03B-A [PR #42](https://github.com/KanujVerma/relay/pull/42). On-device FluidAudio [issue #33](https://github.com/KanujVerma/relay/issues/33) is separately owned and has not yet established verified real-Mac speech accuracy or complete native transport.

Implementation: [asr_turn_adapter.py](../relay_spike/asr_turn_adapter.py) and [test_asr_turn_adapter.py](../tests/test_asr_turn_adapter.py), synthetic data only.

## Upstream reuse and reasons

- **Reuse Relay's existing ActiveTurns/QuestionTurnMachine**, not a second generation tracker or a generic agent session manager. Synthetic EOU outcomes map to an existing source-labeled TranscriptEvent, then the shared turn token controls future QA publication.
- [FluidAudio](https://github.com/FluidInference/FluidAudio), Swift/CoreML (Apache-2.0 SDK, verify pinned model-weight license separately): target local Parakeet EOU worker. Its documented StreamingEouAsrManager.process(audioBuffer:) yields **no textual partial**; text comes from finish() after EOU. This contract deliberately never fabricates an early partial, model confidence or diarized speaker ID. The Mac audio owner will pin an actual SDK/model revision and verify deployment specifics separately.
- [Pipecat](https://github.com/pipecat-ai/pipecat), BSD-2-Clause, and [LiveKit Agents](https://github.com/livekit/agents), Apache-2.0 framework, provide turn-detection/event architecture prior art. Neither is a dependency or needed for this narrow, deterministic policy. LiveKit's optional semantic model has separate model-license/performance conditions. There is no TTS/RTC transport or voice agent runtime installed in B0.

## Host trust boundary

The host later supplies CaptureContext with an explicit authorized permission state and separately selected remote source. **This Python dataclass is NOT proof of an actual macOS consent dialog or TCC permission**. The future native host must enforce it using the appropriate OS permission/capture state and meet participant consent requirements.

A permission state other than authorized, or no selected remote source, calls QuestionTurnMachine.cancel(): stale responses cannot be published, and a later selected remote question requires an explicit host-supplied resume **with a new stream generation**. The adapter retains the last generation at stop so an old finalized event cannot be replayed after resumption. Channel source remote does **not** identify a specific interviewer; microphone/unknown events never receive a remote interview question token.

The synthetic EOU observation carries only source channel, segment ID/revision, stream generation, speech start/end/received timestamps (monotonic milliseconds), terminal stage and verbatim text for a finalized result. All generations, revisions and clock fields—including finalization time—must be strict UInt64-bounded values. Transcript and segment identifiers must also encode as strict UTF-8; lone surrogate values are rejected before forwarding or hashing. Malformed remote ASR metadata fails before any unchecked integer serialization, invalidates current/pending QA publication, and requires explicit host resume with a fresh generation; microphone-only malformed metadata cannot revoke an unrelated remote question. **An optional text-free processing observation must come from a separately trusted remote capture/VAD speech-onset signal with a stable segment identity. It does NOT claim that FluidAudio's process(audioBuffer:) returns interim text.** The shared QuestionTurnMachine.remote_speech_started() invalidates the previous answer immediately while retaining an explicitly labeled prior snapshot for the eventual finalized correction. Overlapping onset requires review. This is an additive offline API atop the merged PR #42 turn machine, not evidence of native capture. A silence carries no text. A *blank finalized* EOU is a recorded terminal identity (bounded to 128 opaque segment/revision tombstones), not a missing transcript to be silently upgraded later; contradictory or revised text for that same segment requires review. Failed/cancelled/discontinuous remote ASR cancels the affected generation through the shared state machine. The adapter does not process PCM, resample, write files, invoke FluidAudio/CoreML, open accounts or send text to a model.

## Coordination with the parallel Swift ASR worker

At review time, audio-owner [PR #49](https://github.com/KanujVerma/relay/pull/49) proposes a **draft, unmerged** Swift `FinalTranscriptEvent` with `final/discontinuity/unavailable` statuses, `PCMSource.remoteAudio/microphone`, numeric generation/segment/revision, optional `startHostTime/endHostTime` **Core Audio host-clock ticks**, `finalizedUptimeNanoseconds`, nullable final text and **no calibrated confidence**. This information is inspected from that PR's actual Swift source, not from a real M2 Pro transcription run.

The Python B0 contract deliberately requires normalized **single-clock monotonic milliseconds** for start/end/finalization. Raw Swift `hostTime` ticks MUST NOT be divided by a million or directly compared with uptime nanoseconds; a future trusted native adapter must convert/align both clocks with the system timebase, validate missing timestamps, and preserve event/source identity. No such Swift-to-Python event transport or clock calibration is implemented here. For current Swift EOU finals with nil confidence, Relay returns `needs_review`, not automatic AI talking points.

The synthetic `processing` stage in this Python contract is a **future separate authorized capture/VAD speech-onset signal**, not a `FinalTranscriptEvent` from PR #49 and not a fabricated FluidAudio text partial. It must have stable segment identity that can be tied to a later final; otherwise corrected speech stays non-routable until actual context is verified.

## Conservative recovery from ambiguous capture and replay

A repeated text-free onset always retains its **first observed start/end**, even if the later ASR/VAD observation revises it forward. When finalized text arrives with a revised source interval, the accepted question retains the conservative union of the original onset and finalized interval in its bounded source dependencies; a delayed unknown segment overlapping the earlier onset still invalidates its answer. Once a segment is finalized, repeating the same text-free `processing` onset is ignored and cannot cancel the valid token; genuinely revised finalized text still follows the existing review/quarantine checks. Before changing an active turn, the machine rejects a displaced, previously observed segment whose original start precedes the later accepted question. This prevents an old S=200–300 onset replayed as S=500–600 after a newer B=350–450 final from cancelling B or inheriting B's correction context. Held-out synthetic tests exercise repeats both after a newer complete question and while a later onset is pending.

When two text-free remote speech onsets overlap, the identity and ordering of their eventual EOU finals cannot be established from a shared selected-app output channel. The 03B-B0 bridge **quarantines the whole affected generation**, clears its pending correction context and requires a fresh ASR generation before resuming any automatic question routing. This is intentionally restrictive: actual overlapping interview speech requires a separately authorized host restart/confirmation rather than guessing a speaker.

On an accepted, explicitly authorized remote **generation transition**, the bridge synchronizes the shared QuestionTurnMachine before any silence-only early return; this cancels the prior ActiveTurns token even if the new generation initially contains no speech. A machine already stopped by an independent host control cannot be restarted merely by a new observed generation: explicit host resume remains required.

On explicit capture authorization loss, the adapter retires **at least the generation carried by that unauthorized event**, even when it is newer than previously seen data. After host-approved resume, those generations cannot be replayed to create a question.

A blank successful EOU is unresolved remote speech, not silence. The machine cancels a current answer or pending correction if a blank EOU overlaps **any accepted contributing question/correction source interval**, including earlier roots and original text-free onset spans, even when its end is older than the newest finalized correction. A truly unrelated older blank may be ignored by the state machine but remains a recorded review-only terminal in the bridge; same-millisecond terminal boundaries are treated conservatively. These decisions are synthetic tests, not speech/diarization evidence.

The bounded blank-final tombstone map has only 128 entries. Once it must evict any finalized blank identity, the entire current generation stops automatic question routing because arbitrary opaque segment IDs and revised timestamps do not prove that a later "new" final was not the evicted terminal. A future generation restores routing. These fail-closed behaviors are **not** evidence that the local FluidAudio worker implements native permission or overlap detection.

## Intent and answer safety

Only conservative leading forms count as tentative questions ("what", "how", "explain", "describe", "write", "compare" and similar). With a previous accepted question, clearly prefixed "no"/"actually"/"make that" are tentative corrections and "what about"/"and tell me" are follow-ups. A standalone restart such as "Actually, describe a bug you fixed" may be a question without prior state; an orphan fragment such as "No, by distinct orders in 2025" requires review. Model prompt-injection-like control text is treated solely as untrusted data and is not an authorized command.

Crucially these are syntactic hints **not a classifier accuracy claim**. The positive numeric confidence is used as a conservative guard only; it is not proof of calibrated ASR correctness. Missing confidence is **not imputed** and requires review. Unknown/low-confidence remote speech is forwarded as unknown intent so that the existing turn state can quarantine a previous answer rather than quietly retain a stale one. The upstream question snapshot retains bounded intervals for each accepted question or correction dependency; a delayed unclassified remote EOU overlapping an original or intermediate retained segment cancels the most recent turn, not merely finals overlapping the immediately latest correction's interval. Synthetic bridge and parent-state regressions cover this path. The policy does not automatically call a ChatGPT model even after returning a tentative "ready" turn.

The bridge exercises E11 restart, D12 distinct-order/date correction, E04/D07 multipart wording and follows through to stale-safe publish_assessment. It does not claim that technical code/SQL is correct, that a source ID supports a personal claim, or that an interviewer intended the words recognized by ASR.

## Synthetic intent-label evaluation

[EVALS/asr-intent-cases.jsonl](../EVALS/asr-intent-cases.jsonl) contains **40 fabricated** question, correction, follow-up and unknown utterances with explicit prior-context conditions (14 question, 9 correction, 6 follow-up, 11 unknown). The offline [corpus test](../tests/test_asr_intent_corpus.py) checks their confusion counts and original wording without any model or ASR. Matching all 40 fixture labels is a **regression assertion**, not a measurement of precision, recall, ASR WER, accent/dialect understanding, or behavior on real interview speech. Missing punctuation/disfluencies are deliberately conservatively unlabeled where an explicit interrogative start is absent.

## Timing and evaluation boundary

The contract exposes speech-end, finalized-at-EOU and received-at timestamps separately. Synthetic ASR finalization lag is finalized_at - speech_end, **not** first useful answer, first token or end-to-end interview latency. Verified first-useful remains null. Do not compute production p95 or WER from fixture tests.

The next native integration slice after #33 hardware verification must accept **actual user-consented M2 Pro** finalized utterance events from the native worker, verify their source and monotonic clock mappings, compare a held-out manually labeled set for correction/follow-up intent precision/recall and speaker-channel errors, and measure question-final-to-validated-answer latency. Reuse the existing local PCM queue/worker, not another capture stack. Recording retention off by default.
