# Role Pack: Epic software developer

Status: initial hypothesis. Adapt to the actual posting, recruiter details, and interview stage. Public candidate reports vary; no question category is guaranteed.

## Focus areas, in priority order
- Practical coding and reasoning: arrays, strings, maps/sets, loops, recursion, complexity, constraints and common edge cases.
- Debugging: isolate observed vs expected behavior, form testable hypotheses, explain trade-offs.
- Data structures and SQL/database basics when relevant: joins, indexes, transactions, schemas and query behavior.
- Engineering: readability, tests, API boundaries, state, integration and teamwork.
- Behavioral/project stories: individual contribution, challenge, alternatives, results, conflict and learning.
- Unexpected prompts: estimation, ambiguous requirements, changing constraints and follow-up optimization.

## Interview answer contract
- Coding: state approach, correctness intuition, time/space complexity and edge cases. Do not invent a test result.
- Behavioral: cite only confirmed facts from the Personal Brain, separate personal from team work.
- Follow-ups: preserve code/problem context; revise when the interviewer changes constraints.
- Ambiguity: identify missing requirements (input constraints, language, scale) before selecting a single algorithm.

## Edge cases to test
Empty and singleton inputs; duplicate keys; integer overflow; Unicode; nulls; unsorted vs sorted assumptions; off-by-one conditions; complexity improvements; contradicting examples; unprovided editor context; interrupted multi-part questions.

## Context to load before a session
Actual role listing and round format, chosen resume version, verified projects, implementation responsibility, known coding language, and any publicly documented interview expectations tagged as unverified.

## Success measure
Short accurate approaches that handle the explicit prompt, avoid unsupported assumptions and preserve context across follow-ups.
