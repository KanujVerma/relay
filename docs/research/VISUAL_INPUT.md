# Optional visual input through the existing plan-OAuth transport

Research only, 2026-10-23. No credentials, account endpoints, inference, screen capture, permission prompts, or private user material were accessed. No implementation, dependency, branch, or index changes were made.

## Recommendation

Make this usable with **one explicit, user-triggered synthetic-image check for the selected OAuth account and model**, then an in-memory capability receipt and a separate one-request attachment permit. Continue using Relay's HTTPX Responses transport and existing bounded PNG port. Do not treat the current `model_supports_images=True` constructor argument, a model-name allowlist, or a cached Codex model catalog as evidence.

This is a proposed application verification policy, not an OpenAI-required probe or an entitlement guarantee. The public documentation establishes conditional image support; it does not document an account-specific modality-discovery contract. A successful probe proves only that this image request was accepted and answered under that account/model at that time.

## Official guarantees and remaining discovery gap

- [Plan-usage preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), fetched today: image input is supported when the chosen model accepts it. HTTP requests need `store:false`, `stream:true`, and the required context in an `input` array. Files upload, audio/video input, image generation and native computer-use tools are unsupported on this route. Use an inline PNG, without Files API or a vision tool.
- [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), fetched today: get the selected account's current catalog from `GET https://api.openai.com/v1/models` using the same OAuth credential used for inference; display visible `display_name` values and send the exact selected `slug`. Refresh on account changes. Inference uses `POST https://api.openai.com/v1/responses`; only `response.completed` establishes completion. The page documents `models`, `visibility`, `slug`, and `display_name`, but does not specify a modality flag or capability/entitlement endpoint. It warns that app-server `model/list` can be bundled or cached.
- [Images and vision](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses), fetched today: Responses user content can combine `input_text` and `input_image`; `image_url` accepts a base64 data URL. PNG is supported. General API size limits are not a reason to increase Relay's stricter 2 MiB/1920-pixel bounds.

**Upstream modality metadata exists, but does not close that gap.** At Codex commit [`f970f4be6783428af0d39527102917a5305c71d7`](https://github.com/openai/codex/tree/f970f4be6783428af0d39527102917a5305c71d7), [`openai_models.rs`](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/protocol/src/openai_models.rs) defines `ModelInfo.input_modalities`, yet missing fields default to both text and images. [`models_endpoint.rs`](https://github.com/openai/codex/blob/f970f4be6783428af0d39527102917a5305c71d7/codex-rs/model-provider/src/models_endpoint.rs) explicitly distinguishes Codex metadata from the public `/v1/models` API. Therefore copying its optimistic default or trusting an app-server field would not verify this SIWC route. If a future official SIWC schema documents an explicit field, Relay can add a strict raw-field verifier; absent or malformed must remain unknown.

The ordinary Python SDK [`Model`](https://github.com/openai/openai-python/blob/56a55f243960e05e6268bb48ba6bf45299b8f90b/src/openai/types/model.py) type has identification/ownership fields, not modality fields. It also has a different shape from SIWC's documented catalog. Neither type should be imposed on the plan catalog.

## Minimal production seam

1. **Trusted credential snapshot.** Extend the existing auth provider with an internal snapshot that returns the bearer credential together with an opaque account identity derived from the already-verified subject/client registration, plus an auth-session generation. Obtain these atomically from the same selected registration; never accept an account ID supplied by a screen frame. Current `active_access_token()` returns only a string, so independently reading an account setting would introduce an account-switch race. Token refresh must preserve the verified identity and invalidate receipts if identity/grant continuity cannot be proved. Keep token material out of receipts, JSON, logs and UI.
2. **Explicit setup action.** Offer `Test visual input and enable` with a short notice that it sends a generated test image using the selected ChatGPT plan. This action authorizes exactly one bounded probe, not capture or a retry loop. Refresh the account catalog and verify the exact selected slug first. Create a small PNG wholly in memory, with randomized colored shapes/grid positions; ask a short question whose expected answer is derived from its pixels and absent from the text prompt. Use the same model, image detail, endpoint, OAuth path and completion rules as production. Correct bounded output plus `response.completed` can issue a receipt; refusal, incorrect output, timeout or malformed output stays unverified. An incorrect answer does not establish that the model lacks vision. This is a connectivity/visual-access check, not an accuracy benchmark.
3. **Host-issued receipt.** A private-construction immutable `VerifiedImageCapability` holds opaque account key, client/auth-session generation, exact model slug, request configuration, endpoint, user-consent revision, issued/expiry monotonic times and verifier-owned object identity. Keep it only in memory for the current session with a bounded lifetime. Revoke on account/model/configuration changes, sign-out, lost plan scope, user disable, expiry or a definitive capability rejection. A serialized Boolean must never recreate it. No extra model or endpoint is selected automatically.
4. **One-request permit.** After existing screen validation/PNG assembly, issue `RequestImageAttachment` against that receipt and the original native request/session/epoch/presentation lease, selected source, selection/permission revisions, original capture time, content/image digests and PNG hash. Require the original provider-issued object and current native ownership. Source change, request supersession, cancellation, pause/end, revoke, age/deadline expiry, or visual change clears this permit and its bytes immediately. Account capability alone never authorizes a new window. A new request gets a new permit; the account capability receipt need not force a redundant network probe for every screenshot.
5. **Send once.** Add an optional typed attachment to `OAuthAnswerStream.complete(...)` and `response_payload(...)`. Revalidate after credential acquisition and immediately before sending; existing source/turn retirement cancels the stream. With an attachment, convert the existing user content string to the array below. Omit the image when no valid permit exists. Keep instructions separate and screen content untrusted. The caller records a local `used_image` receipt so native publication uses `requiringImageIdentity:true`; model output cannot decide that flag.

```json
{
  "model": "<exact selected catalog slug>",
  "input": [{"role": "user", "content": [
    {"type": "input_text", "text": "<existing assembled question/context>"},
    {"type": "input_image", "image_url": "data:image/png;base64,<validated PNG>", "detail": "high"}
  ]}],
  "store": false,
  "stream": true
}
```

Retain existing allowed `instructions`/reasoning behavior; add no tools, Files upload, stateful response IDs, API key, extra service tier or unsupported output-limit fields. Lazy native chunk production and the 32-frame/256 KiB queue remain necessary before this HTTP request.

## Failure behavior and acceptance boundary

[Official errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery), fetched today, defines `subscription_sharing_unsupported_capability` (400): inspect `error.param`, remove the unsupported feature, and do not resend the same invalid body. The param can identify a tool/model/tier instead of an image. Do not classify every 400 as no-vision. Usage-limit/eligibility/auth failures stop plan inference; temporary 503/network failures do not prove missing image support or require clearing credentials. No API-key or separately billed fallback is permitted.

The current HTTPX adapter collapses every non-200 to `request_rejected`. Add bounded parsing that retains only sanitized status, allowlisted error code/parameter category and request ID, never raw provider bodies or images. Probe parsing must handle admission bodies without an `error` object and midstream failure. Do not auto-repeat failed probe/image inference. Before any request, unavailable optional screen context can fall back to the ordinary text path with clear source status; after an image request fails, show its failure and require a new normal Help/retry action for text-only inference. Never silently label an image answer as OCR-only, or publish a screen-dependent answer after its permit retires.

Proposed offline checks: exact optional payload shape; one-image/byte bounds; unknown/default/replayed receipt rejection; account switch during token await; model/consent/source/request revocation; same-label/different-pixel publication veto; bounded malformed/unsupported/error SSE handling; no automatic second request or billing path; original text-only behavior. No tests were run because this task changed only this research report.
